# 沙箱与被测 Agent 以业务操作接口为界，工具层属于被测 Agent

沙箱只提供一套稳定的业务操作接口，承担业务规则、权限检查、事务、幂等性与审计；暴露给模型的工具层（MCP 工具、函数调用 Schema、工具组合）属于被测 Agent，可替换、可比较，但必须经由业务操作接口执行，不得绕过业务约束。之所以不由沙箱提供固定工具：ADR-0001 要求比较工具设计，固定工具层会使这一目标落空；而把评分落在业务操作层，才能让不同工具层的结果可比。

## Consequences

- 两类记录并存：执行轨迹以业务操作为单位，用于确定性评分；工具调用日志记录模型侧的原始调用，用于诊断工具选择、参数错误、重复调用、重试、调用次数、延迟与成本，可作独立诊断指标，但不计入业务正确性评分。
- 被拒绝操作、权限检查、允许与禁止操作均以业务操作为单位定义；在工具层即失败、未到达业务操作接口的调用只出现在工具调用日志中。
- 第一期提供一套参考工具层作为基线。对照实验中应保持规则集版本、初始数据、验收标准、模型、提示词、权限与执行预算一致，只改变被比较的变量。
