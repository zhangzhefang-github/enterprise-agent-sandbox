# 业务规则分两层执行：系统强制层与业务判断层

P2P 规则集中的每条规则必须归属且仅归属一层。系统强制层负责数据完整性、权限边界、幂等性等底线约束，无论 Agent 判断对错，都阻止非法业务状态变更。业务判断层测试 Agent 是否理解业务规则、识别异常并选择正确处理路径；系统可以保留最终安全保护，但"被系统拦下"不等于"Agent 表现良好"。之所以不全部拦截或全部放行：全部拦截测不出业务判断力，全部放行则沙箱不像真实企业系统，结论不可迁移。

## Consequences

- 被拒绝操作不改变业务状态，但必须留存于执行轨迹；它不自动计为失败，由评测器结合任务目标、调用意图与最终业务状态，区分错误操作、合理重试、越权尝试与被拦截的风险操作。
- 一条规则在两层之间迁移，会改变 Agent 的出错空间，属于规则集版本变更（见 ADR-0001）。
- 具体规则的归属逐条决定，三单匹配作为重点场景，需区分发票录入、差异识别、异常处理、过账等阶段。
