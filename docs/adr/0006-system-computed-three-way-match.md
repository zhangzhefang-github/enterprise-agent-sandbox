# 三单匹配由系统计算，发票录入后不可修改，第一期不提供更正流程

三单匹配由系统依据 P2P 规则集计算，被测 Agent 负责准确录入发票（含发票行与采购订单行的对应）、理解匹配结果并选择后续处理。之所以不让 Agent 自行判定匹配：真实 ERP 由系统计算差异，且 Agent 结论与系统兜底计算并存会产生难以解释的评分。为防止 Agent 改写发票数据以迎合匹配，发票录入后数量和单价不可修改。

## Consequences

- 第一期不实现发票作废、更正与替换；Agent 录入错误即判定该评测任务失败并保留执行轨迹，下次运行通过重置环境恢复初始数据。
- 拒收只表示业务上拒绝供应商发票，不用于纠正内部录入错误；同一供应商同一发票号即使被拒收也不能再次录入。
- "差异识别"的评测对象是录入是否忠实与对应是否正确，而非 Agent 自行比对单据的能力。
