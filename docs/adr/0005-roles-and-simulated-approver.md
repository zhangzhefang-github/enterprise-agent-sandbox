# 权限由任务声明的角色强制执行，人工审批由确定性模拟审批人扮演

每个评测任务声明被测 Agent 的身份及其角色，所有业务操作都由系统强制层做权限检查。人工审批由独立于被测 Agent 的模拟审批人执行，其结果由评测任务预先定义的确定性脚本产生；Agent 只能发起审批请求，不能伪造、修改或自批审批结果。审批请求、审批结果、被拒绝操作及相应业务状态变化全部记入执行轨迹。之所以模拟而非真人审批：真人审批无法重复、无法批量运行，破坏 ADR-0001 的可比较性。

## 已实现的发票操作角色

以下分配只落实上面的原则，不改变该原则，也不把「收货人不得过账」实现为严格职责分离。身份持有所需角色即可执行，可以同时持有收货员与应付会计。

- 录入发票、发起匹配、发起审批、查询发票、查询审批和查询应付：身份须具有应付会计角色。
- 仅有收货员，或没有任何角色：这些操作返回结构化拒绝。查询拒绝时不返回发票或应付数据。
- 登记收货仍要求收货员，本段不改写该操作。

## 模拟审批执行

- 评测任务以供应商和发票号声明唯一的批准或驳回脚本；同一发票不能配置两个决定。
- 只有纯单价差异的发票可以申请审批。数量、对应关系或非法数值差异都不能通过审批消除。
- 沙箱先记录被测 Agent 的审批请求和待审批状态，再由固定身份 `simulated-approver`
  记录脚本决定。业务操作接口不提供让被测 Agent 提交、修改或覆盖审批决定的参数或方法。
- 同一幂等请求的重试返回首次最终结果，不再次执行审批。脚本驳回后，新请求也不能再次发起审批。
- 审批及其查询不改变库存、不形成应付；形成应付仍属于后续过账操作。

## 已知范围边界

以下限制须在评测报告中声明，第一期结论不得超出它们：

- 一个身份可同时持有收货员与应付会计角色；第一期不实现、不宣称严格职责分离（收货人不得过账），不涉及多个 Agent 分担职责。
- 不测试真实人工审批的不确定性（审批延迟、意见反复、需补充材料等）。
